# Gleam v1.46.0 security audit

## Scope

Diff: `4f02d27..b64005d`. The release adds the encrypted vault backup (#222 extension and Google Drive, #223 Android Drive and iOS iCloud, #224 follow-ups), fixes five advisories (#214, #219, #220, #232, #233), hardens the release scripts (#220, #230), extends the surface closure check (#216, #217), and carries a Send and activity UX round (#224, #226), the 1% scan fix bonus (#221) and a peers refresh.

Surface paths changed, by theme:

- **Backup key and keyring.** `core/signer/backup-key.ts` (new): a random 32-byte key, wrapped under the vault password in the same Argon2id envelope as the wallets, with AAD binding it to the backup id. Bodies are AES-256-GCM with a fresh IV and the backup id as AAD. `core/signer/keyring.ts`, `extension/src/keyring/server.ts`, `adapters/offscreen-keyring.ts` and `messaging/keyring-protocol.ts` add `importBackup`/`sealBackup`/`openBackup`/`removeBackup`; the key is imported non-extractable, its raw bytes are zeroized in the server after import and blanked in the request, and `clear()` drops it with the wallets' keys. `runtime/handlers/key-session.ts` unwraps it on unlock with the keys the unlock already derived (no second Argon2id run, no stored password) and never lets a failure keep the vault shut.
- **Backup file and restore.** `core/backup/file.ts`, `merge.ts`, `select.ts` (new): only the storage keys listed with a guard are backed up; grants, sessions and caches are not. The clear header is unauthenticated, so the decrypted body repeats the stamp and `bodyMatchesHeader` refuses a mismatch. Restore (`runtime/handlers/backup.ts`) runs only on an empty vault, writes nothing until the key has opened the body and every value has passed its guard, and refuses the whole file on one bad value. Header passkeys are only prompts: a passkey yields a password that must still open the wrapped key. `backup-sync.ts` and `backup-state.ts` write on change while unlocked; a locked keyring defers the write.
- **Cloud transports.** `extension/src/adapters/google-auth.ts` (new) runs the implicit OAuth flow through `identity.launchWebAuthFlow` with a `state` check, scope limited to the Drive app folder; the hour-long token sits in `chrome.storage.session` (trusted contexts only) and holds no key material. `core/backup/google-drive.ts` (new) talks only to Google's Drive API. Mobile: `plugins/cloud-backup` (Android Google sign-in, iOS CloudKit private database in `iCloud.app.gleamwallet`) and `src/adapters/cloud-file*.ts`, which serve the port from the UI thread to the runtime worker over a message channel. `wxt.config.ts` adds the `identity` permission (no install warning); `App.entitlements` adds the CloudKit container.
- **Passkey restore.** `core/models/passkey.ts` takes the enrolment guard out of `handlers/passkey.ts` unchanged; `app/src/passkey/webauthn.ts` and the onboarding restore screens let a passkey open a backup.
- **Advisory fixes.** Approve buttons accept a click only once the review has been shown and focused for a moment (`approval/input-arming.ts`, GHSA-j43v-3mmc-c8hw). A page transaction with a quantity and no target is refused (`provider-params.ts`, GHSA-5wcj-rr77-8rg8). Approving re-checks the lock (`handlers/approval.ts`, `isVaultLocked`, GHSA-jx27-782x-7f53). `UntrustedText` marks the Mongolian and supplementary variation selectors and other hidden characters (GHSA-97mq-9wjp-c2q5). `pack-release.sh` signs only a zip the local rebuild reproduced, through the receipt `verify-release.sh` writes, and the gate allows a version-only change to the two app `package.json` files and nothing else in them (GHSA-m9qf-vmcw-mm45). A `siteWalletMode` push carries its origin and the content script drops one for another origin (`create-runtime.ts`, `content/index.ts`, #219).
- **Previews.** An AO transfer of 1 of a known collectible previews and summarizes on the device as that collectible (`provider.ts`, `approval.ts`, `prepared-check.ts`); `assertPreparedMatches` passes the collectible only for an L1 `transfer`, so the data-item path is still checked as a data item. Lookalike and first-time-recipient notices change in `transfer-review/` and `RecipientWarning.tsx`, display only.
- **Storage guards.** `isValidWallet`, `isValidHardwareDevice`, `isDisplaySettings`, `isLockSettings`, `isThemeSettings` and `isValidNetworkSettings` move into `core/models` so the backup and the handlers share them. `isValidNetworkSettings` in `transfer.ts` was looser than the core one; the stricter guard now applies there too.
- **Build and surface.** `scripts/check-bundles.mjs` fails on a built script no closure covers and budgets the phrase-key worker. The closure check covers the popup, side panel and mobile main entries; `surface.txt` gains the backup and plugin paths. `.dependency-cruiser.cjs`, `eslint.config.js`, the lockfile, `Gemfile.lock` (addressable 2.9.2) and the Capacitor Gradle and SPM files follow. `core/models/network.ts` adds two HyperBEAM peers from the on-chain refresh.

Outside the surface: `apps/points-api` (fix bonus), `scripts/scan`, the site's privacy and terms copy, skills and docs.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`, and a manual check in Chrome and on both phones, including backup set-up, restore by password and by passkey, and keyfile sends.

## Notes

F-1 to F-5 came from community scans and are fixed here; F-3 to F-5 were published as Low once their fixes merged, and F-1 and F-2 publish naming this release as the fix.

F-6 is accepted: the header carries no secret and decides nothing on its own. A changed stamp fails `bodyMatchesHeader` after decryption, a changed wrapped key fails to open, and a planted passkey entry can only ask the user's authenticator for a credential it doesn't hold. An attacker who can write to the account can at most delete or replace the file, which the backup screen reports.

Known limitations: no change.
