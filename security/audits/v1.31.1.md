# Gleam v1.31.1 security audit

## Scope

Diff: `v1.31.0..bf26dab` (#98). Since the v1.31.0 audit (`e984536`), only the audit file and `apps/extension/package.json` changed before the tag. This release changes no extension or app runtime code. It adds the tooling that signs and uploads the mobile app, and it is the first release meant for the app stores.

Surface paths changed:

- `apps/mobile/scripts/release-app.sh` (new):
  - Before any Ruby runs, it requires a clean checkout at a signed, annotated tag.
  - It refuses a `local.properties` with entries other than `sdk.dir`, and any script in `~/.gradle/init.d`.
  - It builds and verifies the web bundle with no credentials in the environment. Only then does it unlock KeePassXC, with the password on stdin, never in argv or the environment.
  - Credentials are exported into a `0700` temp dir outside the repo, which is deleted on exit, and the Gradle daemon is stopped.
  - `--allow-unverified-bundle` needs a typed "yes". Setting the environment variable alone is ignored.
- `apps/mobile/fastlane/Fastfile`, `Appfile`, `Gemfile`, `Gemfile.lock` (new):
  - Every signing lane first re-checks the tag and the clean tree, then runs `verify-bundle.mjs`.
  - iOS signs through cloud-managed signing with the App Store Connect API key, so no distribution certificate is kept on the machine.
  - The team id is a setting (`GLEAM_APPLE_TEAM_ID`).
  - Usage reporting is off.
- `apps/mobile/scripts/bundle-hash.mjs`, `verify-bundle.mjs` (new):
  - The bundle hash is a sha256 over sorted `path\0sha256` lines. Symlinks and special files are refused.
  - `verify-bundle.mjs` requires hash(`dist`) to equal the tag manifest's `mobileBundleSha256`, and hash(native `public/`, minus the two files `cap sync` adds) to equal hash(`dist`).
- `apps/mobile/android/app/build.gradle`:
  - The release `signingConfig` reads the upload key from the environment only. Without it the build is unsigned.
  - The version is read as plain properties from `version.properties`, which is off the surface so a release bump does not invalidate this audit.
- `apps/mobile/ios/App/App.xcodeproj/project.pbxproj` (off-surface), `Info.plist`: `DEVELOPMENT_TEAM` pinned, and shorter camera permission text.
- `.github/workflows/release.yml`:
  - The build job checks that the extension, app, iOS and Android versions agree (`scripts/app-versions.mjs --check`).
  - It runs `pnpm mobile:build` and hashes `apps/mobile/dist` with `bundle-hash.mjs`. Only a value of 64 hex characters becomes a job output.
  - The release job writes it into `release-manifest.json` as `mobileBundleSha256`. Every `${{ }}` value reaches a script through `env:`.
- `scripts/app-versions.mjs` (new): it reads, writes and checks the versions. Each value must match an exact number of lines, and it validates every file before writing any.
- `security/surface.txt`, `.github/CODEOWNERS`: the new release files are added at tier 5.
- `.github/workflows/dependency-review.yml`: `highline` and `rdoc`, fastlane dependencies licensed "GPL-2.0-only OR Ruby", are allowed by package URL and used under Ruby. The GPL deny-list is unchanged.
- `.gitignore`: fastlane output, and key and keystore file types under `apps/mobile/fastlane/`.

Off-surface: `scripts/release-all.mjs` bumps all versions and checks that `open.gleamwallet.app` serves both `.well-known` files (`scripts/well-known.mjs`). `docs/THREAT_MODEL.md` records F-1.

Run:

- `gitleaks git` on the full history: no leaks.
- `pnpm audit --prod`: 1 low, F-2 of v1.30.0, unchanged.
- The full vitest suite (3444 passed), tsc on all eleven projects, eslint, `wxt:build`, `mobile:build`, actionlint, and zizmor (offline).
- `mobile:build` from two different checkout paths gives the same bundle hash, so CI's value can match a local rebuild.

## Notes

No critical or high finding.

- **F-1.** Exploiting it needs a WebView renderer bug as well. A separate `android:process` Activity for the dApp view is the fix if the risk grows.
- **F-2.** Bundler verifies gems over TLS from rubygems.org at the locked versions. Adding hashes needs Bundler ≥ 2.6 (`bundle lock --add-checksums`), and the machine's system Bundler is 1.17.
- **F-3.** The wrapper downloads Gradle over HTTPS from `services.gradle.org`. A checksum is a one-line change to `gradle-wrapper.properties`.
- **F-4.** A signed tag on a commit that is not on `master` fails in CI ("not on master"), so it gets no Release and no `mobileBundleSha256`. `verify-bundle.mjs` then stops the lanes before signing. The only gap is `--allow-unverified-bundle`, which this release's manifest makes unnecessary.
- **F-5.** No build has been uploaded yet, so this release's build numbers (2) are the first either store sees.
