# Gleam v1.54.1 security audit

## Scope

Diff: `a708a8b..5d70867`, 148 commits. Most are `refactor` commits from a codebase-wide cleanup: large files split along their seams, hand-written guards and parsers replaced by zod schemas, repeated helpers shared. The rest are fixes: AO peer reply caps and the copycat-token flag on the wallet's own sends (#386), the main-screen invite notice, and the three audit fixes below. 123 surface paths changed. Each slice was read against its origin at `a708a8b`; moved code was compared line by line.

Surface paths changed, by group:

- Approval (`runtime/handlers/approval.ts` into `approval-grants`, `approval-prepared`, `approval-preview`, `approval-records`, `approval-types`; `pending-codec.ts`): moved with identical logic. `assertPreparedMatches` is unchanged and still runs before every signer and before device payloads are stored. Grant and pending-record guards are zod schemas accepting the same values; `schemaGuard` returns the input, so no stored field is stripped or coerced.
- Dispatch (`dispatch/methods.ts`, `provider-dispatch.ts`, `site-dispatch.ts`, `site-events.ts`, `request-guards.ts`, `schema-guard.ts`, `guards.ts`, `create-runtime.ts`): page dispatch moved out of `create-runtime.ts`. The tier switch is byte-identical; params are parsed before any handler; only `approval: true` methods get `requestApproval`; origins come from the caller context or native attestation, never from params. Tab matching for site events now accepts only http(s) origins, which narrows it.
- Provider and site handlers (`provider-params.ts`, `site-wallet.ts`, `transfer.ts`, `token-preview.ts`): shared id regex and helpers; `resolveTokenPreview` and the fee quote moved out of `create-runtime.ts`. `transfer.ts` now filters contacts with `isValidContact`, so a malformed contact no longer counts as a known recipient.
- Keys and session (`key-session.ts`, `wallet-lifecycle.ts` into `lifecycle-settings`, `wallet-session`, `keyless-wallets`, `wallet-records`; `vault-lock.ts`, `stored-data.ts`): moved verbatim; lock and unlock paths and the keyring are untouched. Session-key entries use `z.strictObject`, matching the old exact-shape rule. Rename and backup confirmation now write through `updateStored`, closing a read-modify-write race.
- Backup (`backup.ts`, `backup-state.ts`, `backup-sync.ts`): guards moved to zod with the same rules; merge and pull rules unchanged. `vaultIsEmpty` counts raw records, so a restore can't overwrite a record the guard rejects.
- Core models (`wallet`, `session`, `passkey`, `guards`, `bytes`, `async`, `arweave-id`, `tag`, `network`, `site-origin`, `approval`): shared `isRecord`, `ARWEAVE_ID` (the same regex as every inline copy), `singleFlight`, `KeyWatchers`, `tagValue`, `concatBytes`, `httpOrigin`.
- AO and Arweave (`core/ao/*`, `core/arweave/*`): signed bytes are unchanged (`concatBytes` and `sha256` are byte-identical to the local copies). GraphQL replies are parsed with zod schemas that require every field the old code read. `capped-body.ts` holds the shared capped reader; balance, slot and Location replies now go through it (#386).
- Points (`core/points/*`, `runtime/handlers/points*.ts`, `points-attest.ts`, `points-invite.ts`): signed message formats unchanged; API replies parsed with zod encoding the old checks; seen-state extracted into `PointsSeen`.
- Reads (`reads.ts` into `activity-reads`, `collectibles-reads`, `price-reads`, `token-reads`), `announcements.ts`, `peers.ts`, `first-run-network.ts`: mechanical split. The announcement URL allowlist and drop rules are unchanged.
- Shell adapters (`apps/extension/src/adapters/*`, `sender.ts`, `popup-window.ts`, `hardware/open-connect.ts`, `apps/mobile/src/adapters/*`): shared helpers. `sender.ts` uses `httpOrigin` with the same check; `isKeyringSender` is untouched. The mobile dApp bridge keeps main-frame and exact-origin attestation and serves only the first channel request.
- App (`hostname.ts`, `address-identity.tsx`, `AddressDisplay.tsx`, `BrowserView.tsx`, `BiometricSection.tsx`, onboarding, `ReceiveView.tsx`, `sendFormSchema.ts`, `WalletDetailView.tsx`, `formatWinston.ts`, `activity/index.ts`): component and helper extractions. The recipient schema still trims, then checks the same address pattern. Onboarding now validates a stored security phrase before skipping its step.
- Build and fences (`.dependency-cruiser.cjs`, `eslint.config.js` and `eslint-rules/`, `check-bundles.mjs`, `bundle-allowlists.mjs`, release scripts, `surface.txt`, `surface-exempt.txt`, package manifests, lockfile): no fence is weakened; a `no-circular` rule is added. Custom ESLint rules moved verbatim. Bundle allowlists are identical except `zod` on `connect.html` and `passkey.html`; the keyring page and `provider.js` lists are unchanged. The release gate's checks are unchanged. `surface.txt` only gains entries; exemptions each carry a reason. New dependencies: `zod` (core, points-api), `@hono/zod-validator` (points-api), `knip` and `jscpd` (dev), all registry packages with integrity hashes.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.

## Findings

| id  | severity | summary | status |
| --- | -------- | ------- | ------ |
| F-1 | low | The hardware-only check counted only records passing the wallet guard, so a damaged or newer-release keyfile record beside a hardware wallet kept auto-lock from ending the session and `isVaultLocked` reported unlocked. No key was reachable: the record can't be unlocked. | fixed |
| F-2 | low | The zod Location page schema made the cursor optional; a gateway claiming more pages without one had discovery re-read page one up to `maxPages` times. Bounded, no steering. | fixed |
| F-3 | low | Two refactor files, `useSwitchWallet.ts` and `useCollectiblesCatchUp.ts`, were neither listed nor exempted, failing the surface-closure test. Neither touches keys or signing. | fixed |
| F-4 | info | `graphqlErrorsSchema` ignores an `errors` array whose entries lack a string `message`, and parses `data` instead. `data` still passes the strict node schemas. | accepted |
| F-5 | info | The activity-entry guard is stricter, and `appendActivityLog` rewrites the log through it, so an entry failing it is dropped. Every entry Gleam writes carries the checked fields. | accepted |
| F-6 | info | `.dependency-cruiser.cjs` lets `core/signer` import all of `core/models`, which now includes `atomic-schema.ts` (zod). Nothing in the signer imports it, and `check-bundles` fails the build if zod reaches the keyring page. | accepted |

## Notes

- F-4 to F-6 change no security property: F-4 and F-5 fail toward refusing data, and F-6 is held by the bundle allowlist.
- Out of this release: CU `result`, legacy `dryRun` and name-state reads still use `response.json()` without a size cap. They read from configured CUs and the peer list, not from any announced node; capping them with `readCappedText` is a follow-up.
- `BrowserView` now reads grants from the query cache, so a failed refetch after an out-of-band revoke can show a site as connected. Display only: the dispatcher checks the grant on every call.
- Known limitations: no change.
