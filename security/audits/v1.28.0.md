# Gleam v1.28.0 security audit

## Scope

Diff: `b7fedd9..6e8193e` (the v1.27.0 audit commit to master after #69).

Surface paths changed:

- `apps/extension/src/handlers/approval.ts`: `assertPreparedMatches` now requires the device-prepared ownership proof (`pointsProof`, `scanAttestation`) to target the signing wallet's own address, not `""`.
- `apps/extension/entrypoints/background/index.ts`, `src/dispatch/methods.ts`, `src/points-attest.ts`, `packages/messaging/src/site-protocol.ts`: new `gleam-points:attest-status` site message. It is site-tier with a strict schema that has no params. It reports only whether the active wallet can reach the attestation window (`no_wallet`, `unsupported_wallet`, `wallet_not_registered`, or ok).
- `apps/extension/wxt.config.ts`: development builds carry the Chrome Web Store public `key`, so an unpacked copy gets the store id.
- `apps/extension/entrypoints/approval/src/ScanAttestationScreen.tsx`: copy only. It now says the attestation signs a message, not a transaction.
- `apps/extension/entrypoints/popup/onboarding/src/OnboardingView.tsx`: one default wallet name changed.
- `pnpm-workspace.yaml`, `pnpm-lock.yaml`: `vite` overridden to `^8.3.3`, resolved to 8.3.4.
- `security/surface.txt`, `.github/CODEOWNERS`: add `points-attest.ts` and `handlers/attest-errors.ts` at tier 5. This closes v1.27.0 F-1.

Signing changes off the surface list, read in full:

- `packages/core/src/points/ownership.ts`: `buildOwnershipTransaction` sets `target` to the owner's address. `verifyPointsProof` accepts the targeted form or the target-less v1.27.0 form.
- `packages/core/src/hardware/ledger/client.ts`: refuses a transaction with an empty target before it reaches the device.

## Notes

No critical, high or medium finding. What the review checked and found sound:

- **Ownership proof target.** The proof is still a format-2 transaction that moves 0 AR, has a 0 fee, and uses `sha256("gleam-points:anchor:" + message)` as its anchor, so it cannot be mined. Setting `target` to the signer's own address adds nothing a third party could spend or replay. The approval handler builds the payload itself with `buildOwnershipTransaction` and then checks it against `target: wallet.address`. A device payload aimed at any other address is refused before signing.
- **Dual-form verification.** `verifyPointsProof` tries the targeted form first and then the legacy form. Both forms are built from the same owner and message, and the signature must verify against that owner, so accepting the legacy form gives an attacker nothing beyond what v1.27.0 already allowed. It keeps Keystone proofs from v1.27.0 valid.
- **Ledger empty-target refusal.** This narrows what the Ledger client accepts. No path that signed before now signs something different.
- **Attest status.** Only `SITE_ORIGIN` reaches it, it opens no window, and it signs nothing. A failure returns `{ ok: true }`, which only changes a button label. The real attest message still runs every check.
- **Dev `key`.** The value is the store item's public key. It is not secret, and `pnpm wxt:build` leaves it out.

F-1 is a gap in what the audit covers, not a bug. It goes in `todo.md`. Adding the paths edits `security/surface.txt`, so if that change lands before v1.28.0 is tagged, this audit's `commit` has to move past it.

F-2 is the purpose of the message: `attest.html` uses it to show the next step. The site can already see that the extension is installed, because it can message it.

F-3 comes from the Node polyfill chain the build uses. The wallet does its own signing with WebCrypto and `hash-wasm`, not `elliptic`.

Release order: the points API has to run the dual-form `verifyPointsProof` from #67 before v1.28.0 reaches users. Otherwise every targeted proof from the new build is rejected.
