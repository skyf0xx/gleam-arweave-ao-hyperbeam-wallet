# Gleam v1.53.3 security audit

## Scope

Diff: `43a2ca3..4cb40eb`. The release adds lock checks to three background methods, stops trusting one gateway for a token's decimals or a Permaweb Name, closes a pending connect approval when the active wallet changes, adds one HyperBEAM peer, and carries the home drawer, address layout and settings tidy-ups from #379 and three dependency bumps.

Surface paths changed:

- `packages/runtime/src/create-runtime.ts`: `removePasskey`, `setSecurityPhrase` and `switchWallet` now call `requireUnlocked()` first, like `deleteWallet` and `setLockSettings`. `resetAllWallets` still removes the passkey without it, as a reset from the lock screen must. A vault with no password never reads as locked, so watch-only and hardware-only installs keep switching. The only UI callers are the wallet switcher, lock settings and the onboarding phrase step, which runs after the vault is unlocked.
- `packages/runtime/src/handlers/approval.ts`: `signsForActiveWallet` no longer exempts `connect`, so a pending connect is rejected on a wallet switch (and refused at creation if a switch landed in between), like a signing request. The connect screen names the wallet it connects, and the grant follows the wallet active at grant time, so the two could differ before.
- `packages/core/src/models/network.ts`: one community peer from `pnpm peers:refresh`. It serves reads only and gets no host permission.
- `packages/runtime/src/handlers/wallet-lifecycle.ts`: the theme setting drops the `weather` flag. Display only.
- `packages/core/src/recipients/memorable-address.ts`, `packages/ui/src/components/wallet/MemorableAddress.tsx`, `packages/app/src/transfer-review/TagTiers.tsx`: the address block keeps two rows on every screen and shrinks its type instead of re-flowing. Every chunk still renders and the copied text is the raw address.
- `packages/app/src/i18n/messages/settings-home.ts`, `packages/messaging/src/protocol.messaging.test.ts`: the removed weather string and its type test.
- `package.json`, `apps/mobile/package.json`, `pnpm-lock.yaml`: vite 8.3.8, `@capacitor/cli` 8.6.2 and dev-only patch bumps.
- `apps/mobile/package.json`, `apps/mobile/plugins/*/package.json`, `CapApp-SPM/Package.swift`, `Package.resolved`, `capacitor.settings.gradle`, `pnpm-lock.yaml` (#378): Capacitor 8.6.0 → 8.6.2, `@capgo/capacitor-native-biometric` 8.9.1 → 8.9.3, `lucide-react`, and `hono` for the Points API. The biometric releases add Android R8 keep rules and a README section; no change to how the password is stored or released.

Read for this audit, off the surface:

- `packages/core/src/arweave/token-metadata.ts`: `queryCheckedTokenMetadata` now returns `denomination: null` when no other gateway answers, as it already did when one disagreed. `loadTokenMetadata` does not cache it, so a token shows as unavailable with the raw amount until another gateway confirms its decimals. This now matches the Lying gateway row in `docs/THREAT_MODEL.md`.
- `packages/core/src/ao/names.ts`: `isNamespaceEntry` needs two hosts to resolve a name to the same carrier. With the default hosts, arweave.net, hb.arweave.net and up.arweave.net all resolve the namespace (checked live on 2026-11-23), so names still list.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.
