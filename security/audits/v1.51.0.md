# Gleam v1.51.0 security audit

## Scope

Diff: `013e710..d0808fd`. The release adds Permaweb Names to Collectibles and lets the holder point a name elsewhere, adds the paper theme, opens dApps in the mobile app from a browse link, adds pull-to-reload in the app's browser, and fixes the community-scan reports filed against v1.49.x and v1.50.0.

Surface paths changed, by theme:

- **Lock.** Deleting a wallet, changing lock settings, stopping or deleting the backup, and "Use Gleam here" are refused once the vault locks (`requireUnlocked` in `create-runtime.ts`), so a screen opened before auto-lock can't make them (GHSA-fgjh-mxfx-wrx9). A background wallet-list refresh no longer counts as use (`useOtherWallets`), so minimizing and restoring the browser doesn't restart the auto-lock timer (GHSA-3hq4-5w33-g48p). A clock set back more than 5 minutes past the last activity locks (`isSessionExpired`).
- **Token decimals.** A token's decimals are fetched from the user's gateway and two others in parallel (`queryCheckedTokenMetadata`, `crossCheckGatewayUrls`). They are cached only when every other gateway that answers agrees. On a disagreement they stay unknown and uncached, so the token is unavailable and an approval shows the raw amount with the unknown-decimals warning. A gateway that doesn't answer has no vote. Token discovery no longer seeds the cache, so every cache fill goes through the check (GHSA-93v9-32v6-33m4).
- **Permaweb Names.** Discovery lists a `carrier@1.0` process as a name only when the namespace's path manifest resolves the label to it (`isNamespaceEntry`, `names.ts`). Changing a name's target is a 1-winston L1 `set` to the carrier (`name-target.ts`): the carrier's live state is read before signing and a name not held is refused; the build is read back with `assertNameTargetMatches` before a keyfile signs, and through `assertPreparedMatches` for a hardware wallet. `readNameTarget` is strict (exactly two tags, no data, 1 winston). The device view takes the label from the preview only when its carrier is the one the payload names. Label and target render through `UntrustedText`.
- **Approvals.** A device-signed request is marked `attempted` in its own write before it posts, so a restart can't post it twice. The primary button shows a spinner until clicks count (`ArmingLabel`). Address tags with the same exact value share one row (`TagTiers`).
- **Request size.** `readBytes` refuses past 2 MiB before copying a byte array, a buffer or a string.
- **Provider.** While Gleam answers in another wallet's slot, `walletName` gives that wallet's name; the app's browser answers as `ArConnect`. `window.gleam` still says Gleam.
- **Mobile.** A browse link (`https://open.gleamwallet.app/browse?url=<page>`) opens an https page in the app's browser (`browse-link.ts`): one `url` parameter, no fragment, no credentials. The page loads like one the user typed. The app's browser reloads on a pull from the top, and hiding it hands focus back to the app page.
- **Points.** A reset removes every Points storage key (`POINTS_STORAGE_KEYS`). An `x.y.0` release opens at least 50 paid scan places.
- **Peers.** `readL1NodeUrls` keeps the shipped nodes the user removed or turned off out of the fallback. `hyperbeam.paralithmarkets.com` joins the shipped peer list.
- **Build and release.** The keyring page carries its own CSP (`default-src 'none'`), which `check-bundles.mjs` checks. `e2e/egress.e2e.ts` fails the smoke run on a request to a host outside `egress-hosts.ts`. `surface.txt` and `CODEOWNERS` list `name-target.ts`, `browse-link.ts`, the egress test and `scripts/scan/`. The scanner ignores for the withdrawn deepmerge and picomatch advisories are gone. The version files carry 1.51.0.

Outside the surface: the paper theme, the collectibles gallery and name screens, the download page, the threat model's entry that a signature tells the site which wallet signed.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.

## Notes

F-4 is accepted: a signed transaction or data item must carry its owner to be checked or posted, and the approval window names the wallet that signs. The threat model now says so (By design).

F-5 is accepted: a lying gateway's wrong collectibles are its accepted residual. Changing the target still needs the carrier's live state to show the wallet as holder, and the `set` only acts on a carrier the wallet holds.

F-6 is accepted: the page gets only Gleam's provider and must ask to connect like any other site.

F-7 is accepted: a wrong value needed a lying gateway on the first lookup of that token, and such a value can't be told from a right one on the device.

Known limitations: no change.
