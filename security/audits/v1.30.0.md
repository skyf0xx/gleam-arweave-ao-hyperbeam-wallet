# Gleam v1.30.0 security audit

## Scope

Diff: `edb14c0..ba12661` (the v1.29.0 audit commit to master after #84). It covers #80, #82, #83 and #84.

Most of the diff is #84 splitting the extension into platform-free packages. Each moved file was compared with its old version after normalizing whitespace and imports. The changes below are the ones that are not a plain move.

Surface paths changed:

- `apps/extension/entrypoints/background/index.ts` → `packages/runtime/src/create-runtime.ts`: the worker builds a `Platform` and hands it to `createRuntime`. The dispatcher, `dispatchProviderCall`, `runProviderMethod`, the site handlers and the startup, idle, tab and install hooks keep their logic. Chrome calls go through ports: `TimerPort` (alarms), `TabsPort`, `ApprovalPresenterPort`, `DeviceKeyPort`, badge and lock icon. The background entrypoint now only wires Chrome events to the runtime.
- `apps/extension/src/sender.ts`, `packages/messaging/src/caller.ts`: the sender checks are unchanged. `callerContext` turns them into a `CallerContext` (`extension`, or `contentScript` with origin and tab id). The extension-page check runs first. `externalCallerContext` passes on only Chrome's `sender.origin`.
- `packages/runtime/src/dispatch/site.ts`, `methods.ts`: `dispatchSiteMessage` checks `caller.tier === "site"` and then `isSiteOrigin`. The dev-host check reads `platform.dev`, which the extension sets from `import.meta.env.DEV`. `methods.ts` drops the `signature` entry.
- `packages/core/src/policy/signing-origin.ts`, `packages/core/src/models/site-origin.ts`: `isSecureSigningOrigin` and the site origin constants moved to core unchanged.
- `apps/extension/src/handlers/key-session.ts` → `packages/runtime/src/handlers/key-session.ts`: the module functions became `createKeySession({ sessionKeys, storage })`. The function bodies are the same. `create-runtime.ts` builds one instance, so one session lock still orders unlock, lock and auto-lock.
- `packages/runtime/src/handlers/wallet-lifecycle.ts`, `approval.ts`, `transfer.ts`, `upload.ts`, `points.ts`: take the `KeySession` and `ApprovalPresenterPort` by injection. `approval.ts` removes the `signature` signing branch. `wallet-lifecycle.ts` adds `showTokenLogos` to display settings. It is validated on write and on read, and a stored record without it loads with the field off.
- `apps/extension/src/adapters/windows.ts`: `WxtWindowPort` became `WindowApprovalPresenter`. It builds the `approval.html?requestId=` URL itself, and a user closing the window is still reported as a dismissal, which rejects the request.
- `apps/extension/entrypoints/provider/` → `packages/provider/`: `GleamProvider`, `installProvider` and `createWindowMessageTransport`. The transport keeps the `event.source === window` check, the 128-bit random request id and the `location.origin` post target. Each call still settles once and times out. The transport is held in a `#private` field.
- `packages/core/src/vault/message-signing.ts`, `packages/messaging/src/page-protocol.ts`, `packages/app/src/approval/SigningApprovalScreen.tsx` (#82): `signature()` removed. `REFUSED_PROVIDER_METHODS` refuses it before any grant check, and no window opens.
- `packages/app/src/approval/`, `packages/app/src/passkey/`, `packages/app/src/screens/onboarding/`, `wallet-detail/` (moved from `apps/extension/entrypoints/`): only import paths changed. Screens get the runtime, the downloads permission and hardware connect pages from `AppPlatform`. `ApprovalRoot` shows a warning when its platform has no sign panel for a device, where before it had a default panel.
- `apps/extension/src/adapters/storage.ts`: adds `setMany`. It refuses null values and mixed storage areas, and writes through one `chrome.storage.<area>.set`. The `storagePort` singleton is removed.
- `apps/extension/wxt.config.ts`: WXT auto-imports are off for `packages/`. The manifest is unchanged.
- `.github/workflows/ci.yml`, `lefthook.yml`: tsc for the three new packages. `.gitleaks.toml`: allowlists the moved upload test at both its old and new path.
- `pnpm-lock.yaml`: the three workspace packages. `fast-uri` 3.1.9 and `undici` 7.30.1 / 8.12.3 (#82). No new third-party package.
- `security/surface.txt`, `.github/CODEOWNERS`: paths moved to the new packages, and `packages/provider/` and `packages/runtime/src/create-runtime.ts` added.

Changes off the surface list, read for their effect on what is signed or shown before signing:

- `packages/core/src/ao/token-state.ts`, `packages/core/src/arweave/token-metadata.ts`: a token@1.0 logo can come from the headers of a `HEAD` on its HyperBEAM compute. That value goes through `tokenLogoUrl`, which accepts only a transaction id and builds an https gateway URL. Logos are display-only. A discovered token's logo is drawn only after the user chooses Show.

Run: `gitleaks git` on the full history (no leaks), `pnpm audit --prod` (1 low, see F-2), and CI on #84 (tests, tsc on every project, eslint, `wxt:build`, CodeQL).

## Notes

No critical, high or medium finding. What the review checked and found sound:

- **Caller tiers.** A message's tier still comes from Chrome's `sender`, never from the message body. `dispatch` refuses an extension-tier method unless `caller.tier === "extension"`, and a content-script method unless `caller.tier === "contentScript"`. A null caller matches neither tier.
- **One session lock.** `createKeySession` is called once, in `createRuntime`, and every handler that touches keys gets that instance.
- **Approvals.** Closing the window still rejects the request. Timeouts still dismiss the window. The approval URL now comes from the presenter, not the handler.
- **Provider.** The page-side protections are unchanged: source check, random ids, origin-targeted posts, one settlement per call. The page could already post any envelope, so a handle on the transport would give it nothing new. It stays private anyway.

F-1 is fixed in the same PR as this audit.

F-2 comes from the Node polyfill chain the build uses. The wallet signs with WebCrypto and `hash-wasm`, not `elliptic`.

This was one reviewer reading the diff. It was not a full pass over the surface.
