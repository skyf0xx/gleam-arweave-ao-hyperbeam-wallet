# Gleam v1.33.0 security audit

## Scope

Diff: `faf0bc6..765a235`. Security-surface files changed:

- `packages/core/src/arweave/transaction.ts`, `packages/core/src/arweave/transfer.ts`, `packages/core/src/vault/signing.ts`: `broadcastTransaction` posts the same signed transaction up to 3 times to the gateway on a 404, 408, 429, 5xx or no answer, then to `L1_TOKEN_NODE_URLS`. A 400 stops. Signing, and what is signed, are unchanged.
- `packages/app/src/approval/AwaitingDeviceView.tsx`, `packages/app/src/approval/SigningApprovalScreen.tsx`: amounts, fees and totals show every digit. A real fee used to read `0 AR`.
- `packages/messaging/src/protocol.ts`, `packages/runtime/src/create-runtime.ts`, `packages/runtime/src/dispatch/methods.ts`: `getPendingTransfers`, at the `EXTENSION` tier like `getTokenBalances`. Pages can't call it.
- `pnpm-lock.yaml`, `pnpm-workspace.yaml`: node-forge 1.4.2, a dev-only dependency through `web-ext`.
- Versions: 1.33.0, with build numbers incremented.

The other changes:

- `packages/core/src/ao/balance.ts`, `collectibles.ts`: only a token node's 404 reads as a zero L1 balance.
- `packages/core/src/ao/token-discovery.ts`, `packages/runtime/src/handlers/reads.ts`: L1 tokens are reported ahead of the Credit-Notice scan, and the cache is 60s.
- `packages/runtime/src/handlers/reads.ts`, `packages/app/src/screens/activity/src/useBalances.ts`: pending transfers come off what can be spent, in the wallet's own screens only. dApp reads stay raw.
- `packages/core/src/arweave/token-metadata.ts`: a denomination over two digits is dropped.
- `apps/site/privacy.html`, `docs/THREAT_MODEL.md`: the two new hosts are disclosed.

`L1_TOKEN_NODE_URLS` adds no host permission. Both nodes answer CORS for GET and POST, and `connect-src` is already `https:`. The manifest's `host_permissions` are unchanged.

Run:

- `pnpm vitest run`, tsc on all eleven projects, eslint, `pnpm wxt:build`, `pnpm mobile:build`.
- Live: balance reads with arweave.net forced to 404, `readTokenSwapHeight` and `queryBlockHeights` against the real send `uMg6z3…`, and re-posts of an accepted transaction to arweave.net and a node (both 200).
- Manual, extension: pending notes, subscript amounts and sends. The mobile apps were not exercised, and `broadcastTransaction`'s node fallback has not run in a real browser.

## Notes

No critical or high finding.

F-5: the nodes are constants shipped in the wallet, and a signed transaction is public and can't be altered. The worst case is a send that reads pending, then failed after 2 hours, with nothing moved.

F-6: the note never reaches a spendable amount or a price, and appears only on tokens the wallet lists.

F-14: neither package has a production path (`pnpm why --prod` lists none). Both are ignored in `osv-scanner.toml` until 2027-01-31, when the scan fails again.

F-15: node-forge has no production path either.

F-7, F-8: each misstates a figure briefly. Neither changes what is signed, and a send above the real balance is refused by the network or the token.
