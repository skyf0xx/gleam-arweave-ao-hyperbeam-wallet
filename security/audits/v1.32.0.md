# Gleam v1.32.0 security audit

## Scope

Diff: `f086191..617c4dd` (#102 to #106 and `feat/ux-improvements`). The changes are the phone UX batch, the stored query cache, read timeouts, the APK release target and the site's download links.

Surface paths changed:

- `apps/extension/src/adapters/query-cache.ts`, `apps/mobile/src/adapters/query-cache.ts`, `packages/app/src/query-cache/`: the app now stores the query cache between opens. That covers balances, activity, collectibles and portfolio history for the active wallet, plus token prices and display settings.
  - It lives in `chrome.storage.local` under `queryCache:` (extension) and in WebView `localStorage` under `gleam:queryCache:` (mobile). Neither holds key material.
  - An allowlist picks what is stored, and each wallet's entry holds only its own address's queries.
  - A cache is restored only after unlock, and dropped when it is older than 7 days or written by another build.
  - A reset clears all of them (`App.tsx`, `ApprovalRoot.tsx`). Removing a wallet sweeps its entry. A pending save is dropped on unmount, so a removed wallet's cache isn't written back.
- `packages/messaging/src/protocol.ts`: `getPortfolioHistory` takes an optional `address`. It stays extension-tier in `methods.ts`, and `reads.ts` refuses an address that isn't stored.
- `apps/mobile/src/adapters/dapp-bridge.ts`: `subscribe` tells the main screen when the dApp page opens, navigates or closes. `close()` forgets the tab even when the native close fails.
- `packages/app/src/approval/ApprovalRoot.tsx`: a reset from the approval window also clears the query cache.
- `packages/app/src/screens/lock-settings/src/BiometricSection.tsx`, `packages/app/src/screens/wallet-detail/src/WalletDetailView.tsx`: layout only.
- `apps/mobile/android/app/src/main/AndroidManifest.xml`, `apps/mobile/ios/App/App/Info.plist`: the phone app is locked to portrait.
- `apps/site-open/.well-known/assetlinks.json`: the placeholders are replaced by the Play app signing key (`41:D5:…`) and the upload key (`80:5E:…`). Both match the keys on record.
- `apps/mobile/fastlane/Fastfile`, `apps/mobile/scripts/release-app.sh`: a new `android-apk` target.
  - It verifies the bundle and signs with the upload key, like `android-bundle`.
  - `gh` must be present, the tag's Release must exist, and the Release must not already have `gleam.apk`. All three are checked before the database is unlocked.
  - The signing variables are unset before `gh` runs. The APK is uploaded as `gleam.apk` and its SHA-256 is appended to the release notes.
- `.github/CODEOWNERS`, `security/surface.txt`: the new query-cache files are added.
- `pnpm-lock.yaml`: adds `@tanstack/react-query-persist-client` and `@tanstack/query-persist-client-core` 5.104.4, the same version as `@tanstack/react-query`.

Run:

- `gitleaks git` over `f086191..HEAD`: no leaks.
- `pnpm audit --prod`: 1 low, F-2 of v1.30.0, unchanged.
- `shellcheck` and `bash -n` on `release-app.sh`.
- Full vitest, tsc on every project, `pnpm wxt:build` and `pnpm mobile:build`.

## Findings

| id  | severity | summary | status |
| --- | -------- | ------- | ------ |
| F-1 | info | The stored query cache is plaintext, so anyone with access to the browser profile or the app's storage can read balances and activity without unlocking. Addresses are already plaintext, and the cache holds no key material. | accepted |
| F-2 | info | Sideloaded APKs are signed with the upload key, and Play installs use the Play app signing key. A user moving from the APK to Play must uninstall first, which deletes the vault unless it is backed up. | accepted |
| F-3 | low | v1.31.2 F-4, unchanged: Android runs the dApp view and the wallet WebView in one renderer process. | accepted |
| F-4 | info | v1.31.2 F-5, unchanged: build numbers go up by exactly 1 per release, so re-uploading a tag needs a new version. | accepted |
| F-5 | info | v1.31.2 F-6: the `.well-known` check is now required (`WELL_KNOWN_REQUIRED = true`), since `open.gleamwallet.app` is live. | fixed |

Severity: critical, high, medium, low, info. Status: fixed, accepted, open.
An open critical or high finding blocks the release.

## Notes

No critical or high finding.

- **F-1.** Clearing the cache on lock would remove the reason for having it: it lets the main screen paint at once after unlock. A reset and wallet removal already clear it.
- **F-2.** Android ships as an APK only while Play is unavailable. The site and the release notes call it a beta. Users have to back up before moving to Play.
